# Sandbox incident and code audit

The reviewed incident baseline is `b2c9aaa`. The final patch also retains the owner-only mint and legacy-sandbox rejection hotfix merged as PR #63 (`9e3b10d`) and includes the separate fake-dollar entry point added by PR #64 (`b763553`), now sharing the hardened v2 implementation.

Scope: `script/Sandbox.s.sol` and `test/SandboxFork.t.sol` at baseline commit `b2c9aaa`, plus read-only Robinhood Chain RPC evidence for the deployment on chain 4663. This is an audit of the sandbox rehearsal path, not a finding that the production stock contracts permit public minting. No transaction was signed or broadcast as part of this audit.

## Baseline findings

| Priority | Finding | Evidence and consequence | Required direction |
| --- | --- | --- | --- |
| **P0 Critical** | Public mint against a pool containing real USDG | `SandboxStock.mint` at `script/Sandbox.s.sol:39` calls `_mint` for any caller. The incident demonstrates conversion of free synthetic stock into 8.016034 real USDG from the sandbox V3 pool. | Give minting an explicit owner or role; use a valueless mock quote asset for sandbox liquidity. Do not reseed this deployed pool. |
| **P1 High** | LP principal has no exit path | `SandboxLp.addLiquidity` mints a V3 position owned by the helper, but the helper exposes neither `burn` nor `collect`. Its `sweep` can withdraw only tokens already sitting in the helper, not liquidity or accrued fees inside V3. The comment at `script/Sandbox.s.sol:213-214` says pool funds are recoverable via `sweep`, which is false for the minted position. | Track the position and add owner-only burn/collect/exit, then sweep withdrawn tokens. Correct the recovery comment. |
| **P1 High** | Price update is multiple broadcast transactions | `price()` calls `SandboxFeed.set` and `SandboxLp.walkTo` under `vm.startBroadcast()` (`script/Sandbox.s.sol:326-331`). A Forge script is not a single on-chain transaction: the feed can update while the pool move is pending, fails, or gets reordered with third-party trades. | Provide one owner-controlled on-chain operation that updates the feed and pool in one transaction, with target and postconditions checked. |
| **P1 High** | Sandbox trades accept effectively any output | `trade()` passes `minOut = 1` to both `router.buy` and `router.sell` (`script/Sandbox.s.sol:369-371`). Thin liquidity and public ordering can produce a materially worse execution while still meeting that floor. | Quote both legs immediately before execution and enforce meaningful minimum outputs or bounded price impact. |
| **P2 Medium** | Public status and multiplier setters | `setOraclePaused` and `setUiMultiplier` at `script/Sandbox.s.sol:40-41` have no access control. An unrelated address can disrupt the oracle pause rehearsal or change the multiplier exposed by the synthetic stock. These calls are separate from the proven drain mechanism. | Restrict both functions to the same explicit owner or role as `mint`. |
| **P2 Medium** | Deployment exposes unbound components between transactions | The original script creates the hook and two deployers before creating the factory. Each component's first-caller `bind()` can be claimed during that window, preventing the intended factory deployment and wasting gas. | Deploy and bind the four components inside one on-chain call. |
| **P2 Medium** | LP accepts an arbitrary owner-supplied pool | The original LP trusts the active `_pool` address without verifying its factory or token pair, and imposes no cumulative callback payment cap. An operator selecting a malicious pool could authorize callbacks that consume helper balances. This requires an unsafe owner action; it is not the incident's unprivileged attack path. | Bind the canonical pool and pair at construction, validate callback type, and cap cumulative input. |
| **P2 Medium** | Fork test covers the cooperative path only | `test/SandboxFork.t.sol` stages, launches, seeds, changes prices, and exercises the rule with an operator-controlled stock. It does not use an adversarial caller to attempt minting, toggling stock flags, draining pool liquidity, or racing a price update. Its comment at line 85 even describes `s.price()` as one transaction, which does not hold for a broadcast script. | Add tests for unauthorized calls, attacker swaps, LP exit, price-update failure/atomicity, and output floors. |

The current design also makes cost guesses especially unsafe. A runtime reviewer used a historical `eth_call` against the pre-drain pool and found that moving the pool from **100.2** to **112** required **0.922053 USDG**. The earlier **8.96 USDG** estimate was wrong. This quote is specific to that pool state and direction; it should not be extrapolated to another liquidity state. Always simulate the exact swap against the intended block and check the funding balance before giving an operator a price-walk command.

## Implementation in the current worktree

The current worktree contains a replacement sandbox in `script/Sandbox.s.sol` and `script/sandbox/`; `script/SandboxFakeUsd.s.sol` is an alternative entry point over the same implementation. These are source-level observations; the changes are not deployed by this audit.

| Baseline issue | Implemented control | Remaining limit |
| --- | --- | --- |
| Public synthetic asset controls | `SandboxStock` and the new six-decimal `SandboxQuote` take an **explicit initial owner** and use OpenZeppelin `Ownable2Step`. Mint, pause, and multiplier setters are `onlyOwner`; zero multiplier is rejected. The feed uses OpenZeppelin `Ownable`, with the LP helper as its owner. | The owner can still mint arbitrary **valueless** test assets. Ownership must be retained by the intended operator. |
| Real USDG in the rehearsal | `stage()` mints owner-controlled `SBXUSD`, and both stock and quote feeds are synthetic. The V3 pool and launch factory use the mock quote rather than real USDG. `SandboxBook` has version 2; script operations check its runtime hash, mock asset bytecode, wiring, and owners, rejecting the old real-USDG Book. | Only new deployments get this separation. Native gas remains real, and a public pool can still be traded or moved by outsiders. |
| LP cannot exit | `SandboxLp` now binds one canonical V3 pool and tick range, exposes `positionLiquidity`, `removeLiquidity` (`burn` plus `collect`), `collectFees`, and owner-only `sweep`. The script's `exit(min0,min1)` removes the full position and sweeps idle mock assets. | Exit minimums must be chosen by the operator in token0/token1 order. `0,0` disables principal slippage protection. The old deployed LP has no burn/collect method: its `sweep` can rescue **idle** tokens only, not its V3 position. |
| Callback and transfer safety | The LP checks canonical pool/token ordering, callback type and active operation, input budgets, deadline, and target price. It uses OpenZeppelin `SafeERC20` and `ReentrancyGuard`. | These controls apply to the new helper, not the old deployment. |
| Non-atomic price changes | `SandboxLp.setPrice` performs the pool swap and updates **both** stock and mock quote feeds in one on-chain transaction. It reverts unless the exact target is reached in active liquidity. | A successful call does not prevent later public swaps; `repeg()` is an explicit owner action to adopt the current in-range pool price. |
| Hook/deployer binding window | `SandboxLaunchBundle.deploy` creates the hook, treasury deployer, token deployer, and factory in one transaction and checks all three are bound to that factory. | The entire `launch()` script still consists of multiple broadcast transactions; the atomic claim is limited to this bundle. |
| `minOut = 1` in `trade()` | `trade(quoteIn,minTokensOut,minQuoteOut)` requires two explicit, nonzero minimum outputs. | The code does **not** calculate a safe quote or reject a caller who explicitly chooses `1`. The operator must set meaningful bounds for both legs; a later failed half-sale may leave bought strategy tokens with the operator. |

These controls protect a **new** sandbox deployment. They do not upgrade the old contracts, reverse the observed transfers, or restore the drained pool.
